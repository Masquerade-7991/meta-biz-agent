## Modules

| Module | Owns |
| --- | --- |
| `inbox.ts` | Chats, replies, thread control, canned responses and macros, the webhook, AI assist |
| `tickets.ts` | Tickets, response targets (SLA), satisfaction, support settings, notifications |
| `supportOps.ts` | Teams, people's skills, limits and availability, routing rules, the escalation matrix and its minute sweep |
| `contacts.ts` | Contacts, fields, segments, CSV import |
| `templates.ts` | WhatsApp message templates (list, create, delete) and sending one into a chat |
| `analytics.ts` / `reports.ts` | The Analytics page, CSV downloads, scheduled report emails |

All of them are workspace-scoped. Sending needs `ownsMetaAssets()`.

## Model

There is one conversation per customer phone. A ticket is one issue inside it. A ticket opens on a handover, a takeover, a team reply or the customer writing again.

## Ticket lifecycle

The rules are in `src/app/support/ticketRules.ts`, shared with Dummy mode:

- Handing the chat back to the AI agent resolves its ticket, with no rating question.
- Unless the agent holds the chat, a customer writing reopens a ticket resolved in the last 3 days. After 3 days, a new ticket opens instead (`source: customer`).
- Waiting on the customer pauses the deadlines (`pausedAt` / `pausedMs`). The due times shift on resume, and nothing escalates while a ticket is paused.
- Reopening restarts deadlines from `clockStartAt`, and escalation from level 0.
- The database allows one open ticket per chat (`one_open_ticket_per_chat`).
- Bulk changes answer `{done, failed[]}`.
- A member leaving or being removed unassigns their work (`cleanUpMember`).

## Routing and escalation

The decisions are pure and shared (`src/app/support/routing.ts`):

- The first matching rule wins. Otherwise the default routing in support settings applies.
- Only available people under their limit get tickets.
- Escalation levels fire in order, once each (`escalationLevel`). They alert by bell, and optionally by email.

Business-hours maths is in `server/support/businessHours.ts`.

## Activity log

Record actions with `trace(kind, data, {entity, id}, changes)`, where `changes` is `{field: [before, after]}`, built by `diff()`.

- Auth routes run outside a workspace, so they use `traceIn`.
- Sentences and areas are in `src/app/activity/activityText.ts`. Add a case there for a new kind.
- Events are kept 2 years and served by `GET /api/activity[.csv]`.

## Analytics definitions

- **Conversation:** has a message from the customer, the agent or the team.
- **AI alone:** the agent answered and nobody from the team wrote.
- **No reply:** neither the agent nor the team answered.

Rows carry `phoneNumberId`. Rows without one count as the default number. WhatsApp spend is per account and per UTC day, so cost per resolved conversation shows only for all agents.

## Sample data

Rows with `sample: true` are stored but never sent to Meta. Tests send only to sample contacts.

Shape how the agent handles specific situations, and let customers tap instead of type.

![The Abilities section with the Skills and Rich replies tabs](/screens/studio-abilities.webp)

Abilities has two tabs: **Skills** and **Rich replies**.

## Before you start

- Your Identity and Knowledge are in place. Most agents don't need any skills at first. Add one only when a specific situation, such as warranty questions or discount requests, should be handled your way.

## Skills

A skill is an instruction for one situation. The agent reads each skill's description to decide when it applies.

### Add a skill

<Steps>
<Step>
### Start
Press **Choose from templates** for ready-made starting points ("Suggested for your business" comes first), or add your own. **Import skills from CSV** adds many at once; the file needs two columns, `name` and `instruction`, and you can download a template.
</Step>
<Step>
### Name it
**Skill name** is a short label so you can find it later (up to 60 characters), for example "Handling warranty questions".
</Step>
<Step>
### Say when it applies
**Description** tells the agent when to use the skill, for example "When a customer asks about the warranty on a product they bought." (up to 1,024 characters).
</Step>
<Step>
### Say what to do
**Instruction** is what the agent should do, in plain language (up to 2,000 characters). One situation per skill works best. **Write it for me** drafts the text once the skill has a name or description.
</Step>
<Step>
### Save
The skill goes to Meta for review.
</Step>
</Steps>

### Review status

Meta checks each skill, usually within minutes. Every save sends it back for review.

| Status | Meaning |
| --- | --- |
| **In review** | Meta is checking it. The agent doesn't use it yet. |
| **In use** | The agent follows it. |
| **Rejected** | Meta refused it, most often because it asks for or mentions sensitive personal information. Edit and save it to have it checked again. |

<small>Source: [Meta — Skills](https://developers.facebook.com/documentation/meta-business-agent/reference/configure/agent-skills)</small>

### Good to know

- The agent applies every skill whose description matches, so skills that cover the same situation can pull in different directions. The console warns about skills that look alike, and when you have many.
- Fewer, clearer skills work better than many small ones.
- Tone, languages and answer length belong under [Identity](/docs/guide/build-agent/identity), not in a skill.
- A skill that still has `[brackets]` to fill in is flagged. The agent would read the brackets literally.
- Deleting all your skills puts the agent back to its default behaviour. It stays switched on.
- Names are converted for Meta behind the scenes, and the console keeps your readable name. If two names would end up the same for Meta, the console refuses the second one and asks you to change it.

## Rich replies

A rich reply is a message the agent sends instead of plain text when it fits: buttons, a menu, a link button, a picture, a location or swipeable cards.

![The rich reply editor](/screens/studio-abilities.webp)

### Create one

Press **New rich reply**. If you have none yet, start from an example (such as "Book a demo", "Visit our website", "Product menu" or "Where to find us") or **Start from scratch**. The editor opens as a side panel with three steps and a live phone preview.

<Steps>
<Step>
### When should the agent send it?
Describe the moment, for example "When a customer asks where your store is". A few quick suggestions sit under the box.
</Step>
<Step>
### What should it look like?
Pick the kind.

| Kind | Good for |
| --- | --- |
| **Buttons** | Up to 3 quick answers. |
| **Link button** | A button that opens a web page. |
| **Menu** | Up to 10 options in a list. |
| **Image** | A picture with a caption. |
| **Location** | A pin on the map. |
| **Cards with links** | Swipeable pictures, each with a link. |
| **Cards with answers** | Swipeable pictures, each with a reply button. |
| **Ask for location** | Asks the customer to share theirs. |

Cards and Ask for location are under **More kinds**.
</Step>
<Step>
### Write the message
Fill in the fields for that kind: the message, button text, link or picture. Each field shows a character count and a clear message if it is too long or missing. The phone preview on the right shows exactly what the customer will see.
</Step>
</Steps>

Give the reply a name at the top of the panel, or leave it and it is named from your "when" text. Press **Save rich reply**. It is live as soon as you save.

### Limits worth knowing

WhatsApp limits how much text each kind can hold. The editor enforces these as you type.

| Kind | Limits |
| --- | --- |
| Link button | Message up to 1,024 characters, button text up to 20, small print up to 60. |
| Menu | Message up to 4,096, button text up to 20, 1 to 10 options, option title up to 24, description up to 72. |
| Buttons | Message up to 1,024, 1 to 3 buttons, each up to 20 characters and all different. |
| Cards | 2 to 10 cards, card text up to 160, pictures at a public web address. |

<small>Source: [Meta — Writing rich replies](https://developers.facebook.com/documentation/meta-business-agent/usage-guides/writing-ui-skills)</small>

### Turn off, edit or delete

Each rich reply has a switch to turn it off and on, plus **Edit** and **Delete** in its menu. Deleting stops the agent sending it straight away.

A rich reply made outside Helo.ai shows "Made outside Helo.ai. Open it to set it up here."

## If something goes wrong

| Message | What to do |
| --- | --- |
| **Say when the agent should send this.** | Fill in step 1. |
| **Another rich reply already has this name. Change the name at the top.** | Rename it. |
| **Another rich reply has the same "when".** | Make each "when" clearly different so the agent picks the right one. |
| **A skill covers the same situation.** | Keep either the skill or the rich reply, or make them differ. |
| **Couldn't save. Nothing was lost.** | Try again. |
| A skill shows **Rejected** | Remove any request for sensitive personal details, then save again. |

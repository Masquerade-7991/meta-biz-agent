Connect a system that has an API, so the agent can check other methods to bring in data instead of only answering from its knowledge.

![The Connections section listing a connection and its tools](/screens/studio-connections.webp)

## Before you start

- The system's web address (starting with `https://`) and a key or credentials. You may want your developer nearby: the form has **Copy a checklist for your developer**, listing exactly what to find.
- The system must be reachable on the public internet over HTTPS.

The **Connections** section has three tabs: **Your systems**, **Ready-made** and **Business events**. Ready-made one-click connections to popular tools are on the way; until then, use **Your systems** for anything with an API.

## How it fits together

- A **connection** is one system, such as your online store.
- A **tool** is one request the agent can make to it, such as "look up an order".

## Steps

<Steps>
<Step>
### Connect a system
Press **Connect a system**.

- **Name**: type it the way you'd say it, for example "Shopify store". Meta only accepts letters, numbers and underscores, so the form shows what it's saved as (`Shopify_store`).
- **What is it for?** One sentence. The agent reads it to decide when this system can help.
- **Address**: choose **API**, where you add each request the agent can make, or **MCP server**, where the server lists its own tools. Then enter the base address every request starts with, including any version. It must start with `https://`.
</Step>
<Step>
### Choose how it signs in
- **Access key**: a key or token. In **Send as**, choose **Bearer token** (the most common), **Custom header** or **URL parameter**. For a header or parameter, name it exactly as the system's documents say (for example `X-Shopify-Access-Token`). Paste the key. If the system wants text before the key, choose **Add text before the key**. **Another key** adds a second one.
- **OAuth (client credentials)**: a token address, client ID and secret, optional scopes, and whether the token request is form-encoded (most systems) or JSON.
- **None**: public systems only. Anyone can call such a system without a key, so use it only for public information.
</Step>
<Step>
### Create the connection
Press **Connect**. Problems show under each field once you've filled it in, or all together when you press **Connect**.
</Step>
<Step>
### Add a tool
Open the connection and press **Add tool**. For an MCP server, press **Refresh tools** instead and the server lists them.

- **Name**: type it the way you'd say it, for example "look up order". It's saved as `look_up_order`.
- **When should the agent use it?** Be specific: when to use it, what it needs and what it returns.
- **Request**: the method (colour-coded: GET green, POST blue, PUT and PATCH amber, DELETE red), and the path after the base address. Put changing parts in curly brackets, like `/orders/{order_id}`. Each one appears under **From the path**.
- **Values it sends**: the tabs **Params** (added to the address, like `?limit=3`), **Headers** and **Body** (JSON; not for GET). Each value is one line: its name, its type, and how it's filled. Click how it's filled to choose: the agent takes it from the chat (say what to take, and whether it's required), it's always the same value, or it's the customer's WhatsApp number.
- **More** holds an optional example customer question, shown in Test & Eval so you can try the tool with one tap.

Press **Save and test** to save and try it straight away, or choose **Save without testing** from the arrow next to it.
</Step>
<Step>
### Test it
Press **Test** next to a tool, fill in sample values and run it. It sends the real request with your saved key. It doesn't message any customer. You see whether it worked, how long it took, and the answer.
</Step>
</Steps>

## Keys

- A saved key is never shown again. The edit form shows only the last characters, for example "Saved key ends in ...".
- Keys live with Meta, not in your browser.
- Editing a connection without changing its sign-in leaves the saved keys alone. If you change the sign-in method, you must enter every key again.

## Connection status

| Status | Meaning |
| --- | --- |
| **Working** | Recent calls succeeded. |
| **Failing** | Recent calls failed. Choose **See errors**. |
| **Not tested yet** | Test a tool to check it works. |

Other notes under the status: "Not connected yet: it needs its key", and "The system stopped accepting the key". Some systems, such as Shopify, issue tokens that expire after about a day. Open the connection's menu for **Errors and stats**, **Edit connection** or **Delete connection**. Deleting a connection removes its tools, and the agent stops using them straight away.

**Errors and stats** shows the last 7 days. Meta keeps only failed calls, so successful chats count in the totals but not in the list.

## Good to know

- Names must be unique. Meta allows only letters, numbers and underscores, so spaces and dashes become underscores when you save.
- Many similar tools make it harder for the agent to pick the right one. Fewer, clearly described tools work better.
- A tool can show success while the other system reported a failure. The test result shows what the system actually answered.

## If something goes wrong

| Message | What to do |
| --- | --- |
| **Use some letters or numbers in the name.** | A name written only in another script or symbols has nothing Meta accepts. Add some Latin letters or numbers. |
| **Use a full https:// address** | The address must start with `https://`. |
| **Something with this name already exists here. Choose another name.** | Pick a different name. |
| **Meta didn't accept the connection...** | Check the name, that the address starts with `https://`, and that every key is filled in. |
| **Enter this key again: changing sign-in sends every key afresh.** | Re-enter all keys. |
| **Save the connection first.** | A tool can only be tested once its connection is saved. |
| **Couldn't run the test** | Read the detail shown. A 401 or 403 means the key is wrong or expired; update it. A 5xx means the other system had an error. |

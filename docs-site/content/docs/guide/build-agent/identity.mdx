Give your agent a name, a job description and a voice, so every conversation starts from the right place.

![The Identity section with the About and Personality tabs](/screens/studio-identity.webp)

Identity has 2 tabs: **About** and **Personality**. One **Save** button saves the changes on both.

## Before you start

- An agent open in the studio. See [Build your AI agent](/docs/guide/build-agent).
- Business details, such as your hours and policies, don't go here. They live in [Knowledge](/docs/guide/build-agent/knowledge#business-details), under **Business details**.

## Steps

<Steps>
<Step>
### Name the agent
Type a name in **Agent name** (up to 60 characters), for example "Aria". The name is only for you, and customers never see it. The exception is when you tick "Agent introduces itself as … when conversations start" on the **Personality** tab.
</Step>
<Step>
### Describe what it does
Under **What does this agent do for customers?**, write a short description (up to 250 characters), for example "Helps customers track orders, browse products and start a return."

Write it as a description of the job, not as instructions to the agent. Plain English works best. If your text reads like a command, a warning asks you to rephrase it.
</Step>
<Step>
### Get help writing it, if you want
Click **Need ideas?** for these options:

- **Write it for me** drafts a description for you to edit.
- **Improve my wording** tidies what you have written.
- **Suggest for … businesses** suggests a description for your business category, when the category is known.
- **Start from an example** starts from a sample, such as an online store, a booking business or a neutral starting point.
- **Draft from a document** suggests a description from a `.txt`, `.pdf` or `.docx` file (under 5 MB) that you upload.

If you already have text, the console asks before it replaces it. Anything drafted from a document is marked "Suggested from your document. Please review and edit."
</Step>
<Step>
### Set the personality
Open the **Personality** tab and choose the options below.
</Step>
<Step>
### Save
Click **Save**. To hear the new voice straight away, use **Try it**.
</Step>
</Steps>

## The Personality tab

| Option | Choices | Notes |
| --- | --- | --- |
| **Tone** | Professional, Enthusiastic, Informal, Custom | **Custom** lets you describe the voice in your own words (up to 250 characters), such as "Friendly and reassuring, like a helpful neighbour." If you choose **Custom** without writing anything, the agent uses the standard professional tone. |
| **Emoji use** | Never, Sparingly, Freely | |
| **Agent introduces itself as … when conversations start** | A tick box | The agent gives its name when a conversation starts. |
| **Answer length** | Concise, Standard, Detailed | Longer answers cost slightly more per message, because Meta charges for the amount of text the agent writes. For most businesses, Concise or Standard reads best on WhatsApp. |
| **Default language** | A list of languages | The language the agent uses, unless a customer writes in another language you have added. |
| **Match customer's language automatically** | A switch | When it's on, you can pick **Additional languages**. |
| **Allow natural mixed-language replies** | A tick box | For customers who mix languages, such as Hinglish. It needs **Match customer's language automatically** to be on. |

Words the agent must never say are set under [Safety and handoff](/docs/guide/build-agent/safety-handoff), not here.

## Good to know

- The agent answers in the language of the customer's message when you have added that language. Otherwise, it uses your **Default language**. Meta says the agent is strongest in English, so test each language you care about before going live.
- Everything on this page shapes every conversation. For a special rule for one situation, such as warranty questions, use a [skill](/docs/guide/build-agent/abilities#skills) instead.

<small>Source: [Meta — Business Agent capabilities](https://developers.facebook.com/documentation/meta-business-agent/capabilities)</small>

## If something goes wrong

| Message | What it means and what to do |
| --- | --- |
| **This looks like an instruction rather than a name / description** | Rephrase it as a plain name, or as a plain description of the job. |
| **We could not find enough in this document to suggest a description** | Write the description yourself, or start from an example. |
| **Use a .txt, .pdf, or .docx file.** | Convert the document to one of those types. |
| **This file is too large. Please choose a smaller document, under 5MB.** | Upload a smaller file. To give the agent a big document to learn from, add it under Knowledge instead. |
| **We could not save your changes. Nothing has been lost.** | Click the retry button on the banner. |

<Callout type="info">
**Draft from a document** only fills in the description box. It doesn't give the agent access to the document. To let the agent use a document as a reference, upload it under [Knowledge](/docs/guide/build-agent/knowledge#documents).
</Callout>

## Frequently asked questions

<Accordions type="single">
<Accordion title="Will customers see the agent's name?">
Only if you tick "Agent introduces itself as … when conversations start" on the **Personality** tab. Otherwise, the name is just a label for your team. On WhatsApp, customers see your number's [display name](/docs/guide/whatsapp-assets#display-name) instead.
</Accordion>
<Accordion title="Which languages does the agent speak?">
It uses your **Default language**, plus any **Additional languages** you add once **Match customer's language automatically** is on. Meta says the agent is strongest in English, so test each language in [Test & Eval](/docs/guide/build-agent/test).
</Accordion>
<Accordion title="Can I upload our brand guidelines?">
Not as a voice setting. Describe the voice in **Tone** with **Custom** instead. **Draft from a document** only suggests a description; to let the agent read a document, upload it under [Knowledge](/docs/guide/build-agent/knowledge#documents).
</Accordion>
<Accordion title="Why does the console say my description looks like an instruction?">
The description should say what the agent does, such as "Helps customers track orders", not tell it what to do. Rephrase it as a plain description of the job, and put rules for particular situations in a [skill](/docs/guide/build-agent/abilities#skills).
</Accordion>
<Accordion title="Does a longer answer length cost more?">
Yes, slightly. Meta charges agent messages by the amount of text, so **Detailed** answers cost a little more than **Concise** ones.
</Accordion>
</Accordions>
